# 钩子库（Hook Swipe File）

阶段 A 写口播稿时必读。用途：把"开头怎么写"从凭感觉变成"选公式 → 填空 → 三层配齐 → 记账本"。

**来源与许可**：结构框架萃取改写自以下 MIT 项目，例句全部按本账号赛道重写：
- motion-team/creative-strategy-skills（`hook-writing` / `hook-tactics` / `hook-voice-patterns`）：三层钩子、心理触发 × 战术两层模型、写作禁忌
- rediumvex/viral-hooks-skill：100 条公式 / 10 类触发、"停留钩 + 留存钩"混搭出候选
- jakeolschewski/social-media-hooks-database：平台差异、文字叠加作为第二层钩子

**效力说明**：这些公式的经验来自英文内容生态，在这里只是**结构骨架和灵感池**，不是效果保证。哪类钩子对本账号有效，只认账本数据（SKILL.md 第 28 条的决策规则）。下面的例句是写法示范，**里面的事实没有核验**，正式用时照常走阶段 A 的核验流程。

## 1. 三层钩子（每条片前 3 秒都要写齐）

| 层 | 是什么 | 独立成立的标准 |
|---|---|---|
| **口播钩** | 第一句话 | 闭眼只听，也想听第二句 |
| **画面钩** | 第一帧的主体：人物、LOGO、实物、场景、动作 | 静音、不看字，也知道"跟谁/跟什么有关" |
| **文字钩** | 第一帧的大字标题（不是字幕） | 只看这行字，就知道反常点或利益点 |

规则：
- 三层**分工，不复读**。文字钩不能等于口播原文；最常见的好组合是"口播抛问题，画面给主角，文字给反差或数字"。
- 文字钩 ≤14 个字，第 0 帧就要在屏，落在 y 400–900 的安全区，手机上一眼读完。
- **正片不接前置封面**，第 0 帧就是钩子帧。封面是单独的点击钩，规则见第 8 节。
- 例（EP5 改法）：口播"你有没有把一段心事发给AI…"（问句）＋ 画面：数字人加聊天气泡 ＋ 文字"她研究AI恋人4年，自己也爱上了"（具体人物加反差）。

## 2. 停留钩 vs 留存钩

- **停留钩**：让拇指停下（第 0–3 秒）。适合：反常识、数字断言、问句痛点、断言揭露。
- **留存钩**：让人看过第 3 秒（第 3–8 秒接住）。适合：具体事件悬念、自曝坦白、身份代入。
- 写法：第一句用停留钩，第二句马上接留存钩（交代"接下来会讲一个具体的故事/答案"）。**不要让第二句是泛泛铺垫**（EP5 的 S02"不用先问你忙不忙…"就是反例）。

## 3. 再钩点（第 15–20 秒、第 35–40 秒）

我们的平均观看时长只有约 14 秒，所以第 15 秒前后必须再给一次理由留下来。可用句式：
- 转折："注意，这些都只发生在文字里。"
- 预告："但真正的问题不在这儿。"
- 揭底数字："调查里有百分之六十的人这么想。"
- 反问："那问题来了，为什么…？"

镜头表里给这句标 `rehook`，画面上要有一次明显的形态变化（换版式、焦点元素入场、音效），不能和前一镜同一个模板。

## 4. 钩子类型（账本 `hook_type` 用这套名字，可以用 `+` 组合）

| 类型 | 触发机制 | 对应英文战术 |
|---|---|---|
| 问句痛点 | 被迫在心里作答 | Question / Pain Agitation |
| 现象指认 | "你一定见过" → 熟悉感 | Relatable cold-open |
| 具体事件悬念 | 故事从中间开始，需要结局 | Story / Curiosity |
| 断言揭露 | 揭穿利益链、"他们没告诉你" | Explainer / Bold Claim |
| 数字断言 | 精确数字激活可信度过滤 | Specificity & Data |
| 反常识 | 与观众已有信念冲突 | Contrarian / Myth-Busting |
| 身份代入 | "这条是给…的人" → 自我筛选 | Identity / Demographic Callout |
| 清单承诺 | 先告诉观众能拿走几条干货 | Listicle & Value Stack |
| 自曝坦白 | 承认自己踩坑或看错 → 信任 | Confession |

## 6. 写作禁忌

- 不用"哈喽大家好""今天我们来聊聊""你知道吗""震惊"开场。
- 第一句不出现账号名、品牌名、"AI不焦虑君"。
- 不写放之四海皆准的空句（"AI正在改变世界"）。每个钩子至少含一个**具体**元素：人、机构、数字、时间、原话。
- 不夸大：钩子的承诺必须在正片 20 秒内兑现，否则完播更差，也违反阶段 A 的核验口径。
- 读出来像广告就重写；用观众自己的说法，不用机构腔。
- 连续两集不要用同一个公式编号（同类型可以，用于积累对比样本，见 SKILL.md 第 28 条）。

## 8. 封面与发布标题（点击钩）

### 8.1 三处分工

| 位置 | 观众在哪里看到 | 任务 |
|---|---|---|
| 第 0 帧 | 视频号、抖音的单列信息流（自动播放，观众看不到封面） | 让人**停下**（停留钩） |
| 封面 | 主页网格、搜索结果、小红书双列信息流、转发卡片 | 让人**点开**（点击钩） |
| 发布标题/描述 | 封面下方或视频底部 | 补充具体信息，放搜索关键词 |

所以封面不拼进正片：放在第 0 帧，等于把单列流里最贵的 0.5 秒浪费在一张静态卡上。

### 8.2 承诺链

封面 → 发布标题 → 第 0 帧文字钩 → 第一句口播，四处讲的是**同一个承诺**，但措辞不重复。观众点进来后第 1 秒，必须看到封面许诺的那个人、数字或反差；看不到就会立刻划走，这就是标题党反噬完播。

### 8.3 封面文案

- 主标题 ≤12 字，最多两行，**只放一个点击理由**：反差、具体数字、具体人物或机构、悬而未决的问题。
- 不用栏目名、"第 X 期"、slogan 做主标题。IP 识别交给统一模板和角标（styles.md 0.3）。
- 关键词高亮最多 2 处，用品牌红蓝。
- 副标题可选，≤12 字，回答"这跟我有什么关系"。
- 不能出现正片里没有的说法，或没通过核验的说法。
- 来源：从选中的钩子候选派生，和文字钩共享同一个核心元素（同一个人、数字或反差），但换个说法。文字钩偏"抛出"，封面偏"概括"。

### 8.4 发布标题

- 和封面互补，不复读：封面给反差，标题给具体人物、事件和搜索关键词。
- 前 15 个字就要有点击理由（列表页会截断）。
- 话题标签 2–3 个，放在末尾。

### 8.5 封面画面

- 主体是真人闭口帧、真实 LOGO 或实物，占画面 ≥1/3。不用生成的嘴。
- 主标题和主体放在画面中部，保证裁成约 3:4（主页网格、小红书）后仍然完整。各平台的实际裁切比例，发布时核对一次后写进这里。
- **缩略图检查**：缩到 180px 宽，主标题仍然能读出来。
- 统一模板（人物位置、版式、配色）照旧，保证主页九宫格整齐。

### 8.6 出稿流程

- 阶段 A 出 3 个钩子候选时，每个候选附一条封面主标题和一条发布标题，用户选钩子时一并选定。
- 阶段 F 渲染封面后，把原图、180px 缩略图、3:4 裁切预览一起交审。
- 定稿后把 `text_hook`（第 0 帧大字）和 `cover_text`（封面主标题）写进 `seed_episodes.py` 的 `COVER`。平台如果提供封面点击率或曝光点击率，一并记录。

### 8.7 示例（EP5，事实待核）

| 位置 | 文案 |
|---|---|
| 第一句口播 | 你有没有把一段心事发给AI，却没发给通讯录里的任何一个人？ |
| 第 0 帧文字钩 | 她研究AI恋人4年，自己也爱上了 |
| 封面主标题 | AI男友会下楼接她 / 可惜只在文字里 |
| 发布标题 | 研究虚拟恋人4年的副教授，谈了一场AI恋爱 #AI陪伴 #情感 |

注意：原报道里"下楼接她"的"她"是研究者本人还是受访者，要按原文核实；如果不是本人，文字钩和发布标题都要改主语。
