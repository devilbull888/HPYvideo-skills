# 第一集（Muse/Amazon，2026-10-18～21）的教训与修法

## 用户验收偏好（直接照做）

| 用户意见 | 固化成的规则 |
|---|---|
| 节奏太慢 | 成片统一加速 **1.25 倍**（`finalize.py`，音画同步变速，音高不变）。脚本按 1 倍速 60–70 秒来写 |
| 只有配音，缺少音效 | 每个动画节点都配一个音效，约每 2 秒一处，和动画共用同一个 TimingMap 锚点。音量 0.18–0.5 |
| 首帧要做成封面 | 0.5 秒封面放在最前面：主标题 + 副标题 + 有冲击力、或结合 IP 的背景（真人高清闭口帧）。另外单独输出一张 PNG |
| 嘴角撕裂、上牙中间有黑点 | 数字人模块一律用 `MODULE_VARIANT=fix` 后处理版本（`tools/mouth_fix.py`） |
| 口型基本对得上 | MuseTalk CPU 加现有母版缓存可以继续使用 |
| 内容和来源标注满意 | 每个数据镜头都要有来源角标："来源：X（据 Y，日期）" |
| 选的是 ElevenLabs 精简标签版（A） | 只用 `[short pause]`、`[calm]`，最多再加一处 `[thoughtful]` |
| 不要"哈喽大家好" | 第一句直接进入钩子 |
| 不用 bypass 模式；长任务先只读检查再授权 | 授权请求里要列清楚：进程状态、输入输出、覆盖风险、锁、日志文件名 |

## 技术坑

1. **WSL 后台进程会被杀掉。** 即使用 `setsid nohup`，会话断开后 WSL 空闲关机，进程也会一起没。长任务要从 Windows 侧用 `Start-Process wsl.exe` 启动。
2. **`Start-Process -ArgumentList` 会丢掉引号。** 引号里的 `bash -c '...多个词'` 会被拆开，结果只执行了第一个词。解决办法是把要执行的命令写进一个 `.sh` 脚本，只传脚本路径和不含空格的参数。
3. **工具会预先展开 `$VAR`。** 命令里直接写完整的解释器路径。
4. **Windows 侧的内存守卫在 WSL 里读不到值（返回 null），而当前代码把 null 当成放行。** **已在第四集参考实现修复**：读不到即视为不安全，并由 Windows 侧 `tools/winmem_writer.ps1` 写 `work/winmem.txt` 兜底。
5. **torch 的 `setup_torch()` 在同一个进程里只能调用一次**，因为 interop threads 设置第二次会报错。
6. **音频特征会少一帧**（例如 4.4 秒 × 24 帧得到 105 帧，需要的是 106 帧）。代码里已经做了补齐：用最后一行补，最多补 2 帧。
7. **镜头之间出现空白帧**：v1 在 34.4 秒有约 7 帧空白页。规则：前一个镜头的结束点取 `max(句尾+12帧, 下一个镜头起点)`。
8. **变速后音频比视频长 0.1 秒**，是尾部静音造成的，QA 判失败。已在 `finalize.py` 里加 `-shortest` 修好。
9. **数字滚动从 0 开始**时，前几帧会显示"约 0 亿"。可以考虑从目标值的 60% 开始滚动。
10. **`tools/qa.py` 报告的 freeze_segments** 大多是信息卡停留，不是卡帧，但也说明节奏偏静。一屏静止不要超过约 2 秒（1 倍速下），超过就加微动或二次揭示。
11. **嘴部检查裁剪图**要以嘴的边界为中心，而不是检测框中心，否则嘴会被裁掉。
12. **GFPGAN 没有采用**：MuseTalk issue #244 反映会导致嘴唇抖动，issue #7 说修不了牙齿问题，而且依赖很重。嘴部问题优先用 `mouth_fix.py` 调参解决。
13. **没有安装 ASR**（whisper / faster_whisper 都没有）。对齐用的是静音间隙加动态规划。画面元素出现时间按字符比例估算，可能和对应的词相差约 ±0.5 秒。如果用户要求精确对齐，可以在 ElevenLabs 导出逐字时间戳。

## 第四集（peixun，2026-10-24～26，`peixun_v10.mp4` FINAL_READY）总结

v1→v10 返工的根因：停驻、对齐、数字人余量的规则**早已写在 skill 里，但只靠抽帧看"出没出现"，没有逐元素核算帧数**。由此新增 `tools/audit_timing.mjs` 硬门禁（SKILL 20.1）。各项细节如下。

## ep4 补充：停驻与对齐要做"逐元素审计"，不能只抽查出现

- 元素入场锚在句尾字位（如「没有错」「讲清楚」「就能解决」）时，要核算"入场帧 → 镜头切走帧"≥45帧（1×1.5s）；句尾才出现的元素宁可提前到句中字位入场（规则允许早于旁白，禁晚于0.3s）。
- 跨句镜头边界：下一场景的语义画面要在对应句首字位进场，不要等句子的形式起点（承诺卡应跟"对方说"进场，不是等S03）。
- Shot 统一6帧交叉淡化（from-6挂载淡入、to-6起淡出），消除硬切冲撞；勿回退成裸帧区间判断。
- StepGap 类"出现→消失"动画要算清间隔：入场到消失的间隔<30帧就是闪烁，宁可常驻不虚坠。

## ep4 补充：数字人退场两条硬规则（v8 修复）

- 窗口尾部必须 ≥ 句尾 +0.2s（§E12 的余量不是可选项）；不能为卡 ≤16s 总预算剪尾——尾帧可断点续推，成本只有增量几帧。
- 退场动画：窗口最后 ≥18f 渐隐 + 轻微下沉缩小（缓出），禁止 ≤8f 纯透明度闪没；渐隐起点允许盖住句尾，人"说着话淡出"最自然。
- 窗口延长后要删 work/presenter/<P>/body16k.wav + audio_features.npy 再跑（clip 阶段会拿旧缓存对长度断言失败），帧级缓存可续跑。

## ep4 补充：相邻数字人窗口应合并为连续在场

- 规则盲区（已立规）：两段数字人窗口间隔 <8s 且语义上属同一"段"（如结尾 判断句→提问→slogan）时，应合并为一张卡连续在场，不要"退场再入场"；≤16s 预算是成本控制软约束，可为连贯性让路。
- 实现：PresenterCard 支持 id2+splitS 双段联播（一张卡播两个 Sequence，人在场不中断）；配合 moveAt/top2/scale2 可在新句进场时平滑移动几何（小卡→大卡"走上前来"）。窗口延长仍走断点续跑：同起点时旧帧全部续用，只推增量帧。

## 第五集 aibanlu 进行中（2026-10-26～27，12 号手绘线条首用）

### 已验证新资产/管线

### 踩过的坑

- **SVG 内放 `<div>` 静默不渲染**：`<Sketch>`(svg) 里的文字标签必须 `<text>`；初版全部 Hand label 死了一轮才发现。
- **测试片加速链**：`asetrate=R*1.25,aresample=R,atempo=0.8` 的实际效果是时长不变+音调 +25%（用户看到"嘴型过快"）。加速且保调就用 `atempo=1.25`（finalize.py 同链），别再手写 asetrate 组合。
- **12fps 抖动要按成片速率反推**：线条变体切换率 ×1.25 = 成片观感。目标 ~6/s（用户实测选定）→ 1× 需 4.8/s → 槽位 `[6,7,6,6]`。候选参考：12/s 成片过快发躁；6/s 成片用户确认合适。关键帧静帧评审验不了动感，12 号必须加渲 10s 动图切片（styles.md 阶段 D 已提示但未强制，建议立规）。
